# Оптимизация импорта растров и исправление масштаба DEM

- **Дата:** 2026-09-06
- **Автор:** opencode (модель Z-AI GLM-5.3-Flash)

## Кратко

Ускорен и защищён от вылетов импорт больших растров, исправлена растянутость рельефа по оси Z при импорте DEM.

## Подробно

### 1. Защита от вылетов при импорте больших растров

- Оценка потребления памяти **до** загрузки данных (`core/georaster/estimator.py`): учитываются чтение, конвертация во float, буфер текстуры Blender (16 байт/px) и mesh. Бюджет — доля свободной RAM (`core/utils/meminfo.py`, без psutil).
- Новая политика **Oversize policy** в диалоге импорта: *Abort* (отказ с пояснением) или *Adjust automatically* (авто-уменьшение плотности mesh).
- Автоматическое **понижение разрешения DEM-текстуры** (`Max DEM texture size` в настройках) через потоковый `gdal.Translate` — память ограничена независимо от размера файла.
- Чтение данных сразу во float32 через GDAL (`buf_type`) — без промежуточной копии массива; блочная запись TIFF вместо полной копии в памяти; явное освобождение данных; прогресс-бар при импорте.

### 2. Ускорение

- Построение mesh из DEM переписано с питоновского цикла на numpy + `foreach_set` (`operators/utils/mesh_builder.py`) — на порядки быстрее и в разы экономнее по памяти; совместимо с Blender 4.1+/5.x (fallback на `from_pydata`).
- Векторизован UV-маппинг больших мешей.
- `replace_nans` (заполнение nodata): копирование массива через `astype` вместо двойного цикла, ранний выход.

### 3. Исправлен масштаб рельефа (растянутость по Z)

- Причина: вершины строились в «сырых» единицах CRS (градусы для EPSG:4326), а высоты — в метрах; масштаб сцены `geoscen.scale` игнорировался (мёртвый код `# TODO`).
- Теперь все режимы импорта георастра (PLANE, BKG, MESH, DEM, DEM_RAW) и импорт ASCII-grid следуют конвенции сцены «1 Blender-юнит = `scale` единиц CRS», а высоты переводятся в единицы горизонтальной системы координат — рельеф получает истинные пропорции 1:1 и корректно совмещается с подложкой. Сила DISPLACE-модификатора масштабируется тем же коэффициентом.

### 4. Авто-детекция неверно указанного CRS растра

- Если выбрана метрическая СК (например, EPSG:3857), а координаты растра лежат в диапазоне градусов (±180°/±90°), CRS автоматически исправляется на EPSG:4326 с предупреждением — раньше это давало резко растянутый меш.
- `SRS.isGeo` распознаёт Web Mercator и UTM без GDAL/pyproj; вычисление Z-коэффициента перенесено после установки CRS сцены (раньше в чистой сцене коэффициент считался неверно).

### Верификация

Автономные тесты numpy-логики mesh-билдера (сравнение с legacy-алгоритмом: nodata, step, masked, winding, scale/zScale), векторизованной UV-математики, `replace_nans` и `SRS.isGeo` — все пройдены; все изменённые файлы компилируются. Протестировано пользователем в Blender 5.2.
